## 1. 架构现状（关键事实，均已读源核实）
- 队列：`breadth_index_tasks`（op=pending/processing/done/failed；rev+claim_token+lease 900s；退避 30s→1h；MAX_ATTEMPTS=8）；worker upsert→canonical-qa `/api/index/upsert`（一次写入向量+BM25+图谱输入），delete→`/api/index/delete`+`/api/index/record-mutate`；epoch 重放（`qa_replay_state`）。
- canonical-qa：基础索引（静态，全部为广度管线记录）+ 增量索引 `incremental/index.pkl`（chunk meta 含 `chunk_metadata` 直通字段）；图谱 = 静态 graph-export.json ∪ 增量 meta 实时推导碎片（`graph_fragment.build_fragment`，按记录去重共现）；orchestrated_search：decompose→hybrid(向量+BM25 RRF)→novelty→graph 邻居补充→rerank→evidence grading。
- 已知缺陷（本规格修复）：
  1. uploads.py::_serialize GitHub 分支固定 `ingestion_status="imported"`——不反映三路真实状态；app.js loadLibrary 对 github 分支 early-return，不轮询。
  2. orchestrated_search 在 hybrid 空时直接 return——图谱路不可独立召回。
  3. `/api/graph` 无栏目过滤：行业/ATSC 增量记录混入门户背景图。
  4. 检索无来源范围；`_upsert_payload` source_type 恒 "breadth-import"；Docling chunk metadata 无 primary_section。
  5. table_rows.py：无类型映射槽位、intelligence_type 恒 "news"、content_hash 不含类型、source_ref.row 是筛选后数据行号、MAX_ROWS 静默截断、校验只到预览 20 行语义（入库前无全量类型校验）。

## 2. 设计

### 任务三（先做：类型是任务一/二的状态与归属输入）
**3A 后端 table_rows.py**
- `MAPPING_SLOTS` += `"type"`；表头精确识别「情报类型」（去空白后全等；禁子串匹配，避免「新闻类型/分类/行业类别」误认）。
- `TYPE_VALUES = {"新闻": "news", "文献": "literature"}`；仅去空白（含全角空格），其余值一律非法。
- `require_type` 参数（仅 breadth/other 入口为 True；行业/ATSC/GitHub 不受影响）：缺映射/列不存在/任一非空行类型空或非法 → `TableParseError`，消息含 文件名/工作表/物理行号/列名/原值/原因。
- 物理行号：xlsx `enumerate(ws.iter_rows, 1)`；CSV 用 `reader.line_num` 推起始物理行（含引号换行）。`TableSheet.row_nos` 与 rows 对齐；`source_ref.row` = 物理行号。表头前空行/表间空行自然计入。
- 超限：>MAX_ROWS 显式 `TableParseError`（不再截断）。
- 全量先校验后入库：两阶段——先纯函数校验全部行并构造字段，任一类型错误在 DB 写入前抛出；上传端点既有清理路径（删 UploadedFile+IndexTask+落盘文件）兜底文件级原子性。
- 身份去重/更新：行身份 = `sha256(json([t,d,u]))`（与 canonical_record_key_sha 同源）。撞身份：内容+类型全同 → skipped_duplicate；不同 → UPDATE 该记录（含类型）并计 `updated`。content_hash 加入 `"i": intelligence_type`。类型修正不再被吞、不产生重复记录。
- 逐行模式行业/ATSC：类型列可选（映射了就严格用，未映射保持现状默认 news）；require_type=False。

**3B 前端 app.js**
- upGuessMapping 增 type 槽（精确别名「情报类型」）；配置对话框增「情报类型」行（breadth/other 显示必映射提示）；预览表格展示类型列原值与问题提示（前端预检仅提示，后端校验为准）。

**3C 类型贯通**
- 入队 payload metadata 已带 intelligence_type（现状）；breadth 页过滤用 DB 字段（现有）。补：类型修正 UPDATE 后重入队（身份更新逻辑内自然发生）。

**3D 历史修复**
- `backend/scripts/repair_row_intelligence_types.py`：找 source_ref 含 sheet 的行记录 → 原文件可读且行可按身份对上 → 干跑预览（--dry-run）→ 备份（--backup JSON）→ 幂等 UPDATE + 重入队；对不上的输出清单保持 pending，不猜测。

### 任务二（归属与检索）
**2A 归属贯通 + 回填**
- `BreadthManualRecord.origin_section`（String(20)，nullable；alembic 0033，down 为 drop_column）。写入：github/other→"breadth"；行业/ATSC 逐行与 sync 上传 → 上传记录 primary_section。
- 回填：0033 迁移内按 `upload_id → uploaded_files.primary_section` 回填（FK 可靠匹配）；不可追溯保持 NULL（单独列出，不猜 breadth）。
- `_upsert_payload`：chunk_metadata.primary_section = origin_section；source_type 按栏目 `breadth-import/industry-import/atsc-import`。
- `request_incremental_index`（Docling 上传）：chunk metadata 注入 primary_section。
- canonical-qa 新端点 `POST /api/index/metadata-patch`（token）：按 document_id 原位更新 chunk_metadata（不重嵌入），标脏碎片缓存；用于存量增量索引归属回填。
- 回填脚本 `backend/scripts/backfill_incremental_sections.py`：DB 可追溯 → patch；canonical 侧无归属文档清单（新增于 /api/index/status 响应）如实报告。

**2B 三源三路检索**
- `/api/search?sources=breadth,industry,atsc`（默认三源全开）；portal agent 透传（用户显式限定则收窄——本期 API 支持，前端不做限定控件）。
- 候选获取阶段来源过滤：基础索引全量=广度域；增量按 `chunk_metadata.primary_section` 分域。向量：行掩码子阵 top-k；BM25：增量子语料建子索引（小），基础不拆。无归属增量行：默认三源模式包含并在 trace 计数（回填后趋零）；显式收窄子集时不包含。
- 图谱独立召回：hybrid 全空不再 early-return；实体匹配→邻居扩展→`_bm25_by_label` 召回原文。碎片按 scope 过滤（静态图=广度域；行业/ATSC=各自增量碎片）。共现边标注 `co_occurrence_aggregate`（现状保留）。
- trace：`retrieval_trace.source_route_matrix[source][route] = {executed, candidates, duration_ms, degrade_reason}`；单路失败其余路继续；「无证据」≠「路失败」。
- 三源各自 RRF/rerank 后跨源融合（上下文预算按源分配，RRF 跨源可解释合并不加裸分）。

**2C 门户背景图谱（2.4）**
- `/api/graph?scope=breadth|all`（默认 breadth）：服务端在度数/标签/计数计算前过滤；静态图全量=广度；增量碎片按 primary_section=breadth 过滤。缓存按 (scope, 签名) 键控。github_qa.graph_snapshot 显式 scope=breadth。
- 行业/ATSC 图谱仅用于各自栏目问答，不进门户背景。

**2D 答案 SOP（2.3）**
- agent_service._build_prompt 重构为按证据来源组织的默认结构：直接回答→行业→ATSC（历史判断措辞）→广度→综合（一致性/冲突/影响）；简单问题短答；某源无证据不编造也不用他源顶替；外部转录不写成 ATSC 自证结论；推断标注。检索结果按来源分组传入。
- 保留并回归验证：answer_status/claim_check/knowledge_boundary/事实核查 fail-closed、引用编号全局唯一、历史引用重核、SSE replace/done、多会话并发。

### 任务一（状态契约，消费任务二/三的归属与类型）
**1A 状态契约**
- canonical-qa 新端点 `GET /api/index/status?document_ids=...`（token）：每文档返回 chunks/vector_ok/bm25_ok/entity_count（实体来自碎片抽取，0=无适用实体非失败）/content_shas。
- api 新端点 `GET /api/uploads/{id}/index-status`（登录）：聚合 包导入结果（breadth_import_sessions 计数）+ 广度页面状态（DB 行可见数）+ 队列任务计数 + 三路状态（done→按 index/status 确认；确认失败/缺文档→待核实；被后续包更新/删除→已失效）+ 每记录明细（前 100 条+汇总）+ 版本/时间。
- `_serialize` GitHub 分支：按队列聚合映射真实状态（index_failed/index_processing/index_queued/indexed/import_failed/legacy_unknown），列表端点单条 GROUP BY 查询聚合（不逐行打 canonical-qa）。
- 重复包/零新增包：session.replayed/package_deduplicated 语义透出（幂等重放≠新导入）。
- 历史无任务且 skipped 的旧包 → legacy_unknown（待核实，不默认可检索）。

**1B 前端（1.3）**
- 移除 github 分支 early-return；状态列显示 导入结果+广度页面+向量/关键词/图谱 四态徽标；行展开详情（明细/进度/失败原因/版本/时间，按需拉 index-status）；pending/processing 自动轮询；失败显示可读原因+重试按钮（走既有 admin retry 端点）；刷新/重登后状态恢复。

**1C 恢复循环（1.2）**
- 既有队列机制保留（rev/lease/退避/epoch 重放/墓碑/版本拒收）；补：三路状态以 canonical-qa 实际内容确认为准（"收到写请求"≠"已可检索"——确认读的是索引本身）；retry 不重复插入同批（幂等 upsert + 身份去重已保证）。
