# 合并路径：SOFC 竖井验证，现有系统全程不动

新体系（判断树 + 文档核心资产 + 跨领域扫描，ADR-0003~0010）不采用全量重构或旁路并行，而是**一条竖井打穿**：选定 SOFC（3 篇高质量文档、专利包、数据锚点、商业就绪度元数据最全），把全链路在该领域跑通——文档结构化提取 → 判断树 → 信号规格 → 挂载广度观测 → 重审触发 → 认知面板 → 跨领域扫描占一行。

理由：新体系含大量未经实战检验的设计（四维+四类在真实领域的归类、文档→树提取准确率、断点体验），首次真实调研是最好的试金石；竖井用最小代价拿到检验，现有系统零改动零风险。

两阶段：
1. **迁移式**（先）——用现有 SOFC 文档盘活存量：验证提取、树、面板。
2. **生成式**（后）——新领域从零调研：验证调研管线与断点设计（ADR-0010 附注）。

竖井阶段不进生产数据库：先用文件（JSON/SQLite）+ 脚本验证，schema 稳定后再正式化建表（届时另立 ADR 决定与 parameter_observations/boundary_summaries 的表结构合并）。

_Avoid_: 全量重构后切换（新体系未经验证，返工成本极高）、旁路生长（两套"唯一现役答案"违反知识唯一性）
